# Mothr mobile

A native phone app for controlling the Mothr desktop app from anywhere: read chats as they
stream, approve permissions, answer agent questions, send/queue/steer messages, run slash
commands, start new chats, use a chat's terminal (a shell on the desktop, in the chat's repo)
and watch usage limits. It stays connected in the background and notifies you when an agent
needs you.

Agents still run on your computer. The phone talks to the desktop's remote-control server
(the same one the web client uses), on the local network or through Tailscale / Dev Tunnels.

## How it's built

| Layer | Where | Shared with desktop |
| --- | --- | --- |
| Session model, reducer, protocol, view models | `crates/mothr-client` (Rust) on top of `crates/mothr-core` | Yes: the same `SessionState::apply` reducer the desktop and the web client run |
| Kotlin bindings | Generated by UniFFI through [Gobley](https://gobley.dev) at build time | — |
| UI | `composeApp/src/commonMain` (Compose Multiplatform, native, no WebView) | One UI for Android and iOS |
| Platform hosts | `composeApp/src/androidMain` (Activity, connection service, notifications), `iosApp/` (SwiftUI shell, notifications, background refresh) | — |

The Kotlin side has almost no logic of its own. `AppModel` waits on
`MothrClient.waitForChange()` and re-reads the flat view records (`chatGroups`, `chat`,
`usage`, …) into Compose state. Commands are plain method calls (`send`, `respondPermission`,
`answerQuestion`, `newChat`, …).

## Background and notifications

When an agent stops to ask for a permission or to ask a question, the phone notifies you, even
when the app is closed. The list of requests comes from the shared Rust client
(`MothrClient.attention()`), so both platforms agree on what counts. `AppModel` notifies once
per request, only while the app is off screen. It withdraws the notification as soon as the
request is answered anywhere: on the phone, on the desktop, or from the notification itself.
Platforms plug in through the small `Background` interface in `Mothr.kt`.

- **Android:** while paired, a foreground service (`ConnectionService`, type
  `remoteMessaging`) keeps the connection open. It shows a quiet ongoing notification ("Connected
  to …" / "2 chats need you") with a **Disconnect** action, which stops it until you open the
  app again. Requests appear on the high-priority "Needs you" channel:
  - **Allow once / Deny** buttons for permissions.
  - The answers as buttons for a single-choice question with up to three options.
  - Tapping the notification opens the chat; for a subagent, it opens under its orchestrator.

  Android 13+ asks for the notification permission after pairing. If Android kills the
  process, the service restarts and reconnects on its own.
- **iOS:** iOS doesn't let apps keep a socket open in the background. Mothr stays connected for
  iOS's short grace period (about 30 s) after you leave the app, then checks in through
  background app refresh, which iOS schedules at its own discretion. Each check posts local
  notifications with the same quick replies. For instant delivery on iOS, the desktop would
  need to send pushes through APNs, which needs an Apple developer key and a relay server.
  That isn't built.

"Run in background" in the chat list's settings menu turns all of this off. The app then
disconnects whenever it leaves the screen.

To try it with the demo hub, start a chat from the desktop side with "permission" or
"question" in the prompt. Add "later" to delay the request by 8 seconds, so you have time to
leave the app:

```sh
curl -H 'Authorization: Bearer devtoken-devtoken-devtoken' -H 'content-type: application/json' \
  http://127.0.0.1:7979/api/command \
  -d '{"type":"new_session","agent":"codex","kind":"chat","project":"/tmp/x","mode":"ask","prompt":"Pick a db, question later"}'
```

## Requirements

- Rust with the mobile targets. Gobley runs `rustup target add` for you. Gobley 0.3.7 can't
  read the build-dir layout of Cargo 1.100+, so build with an older toolchain:
  `RUSTUP_TOOLCHAIN=1.93.0 ./gradlew …` (CI pins the same).
- JDK 17.
- **Android:** the Android SDK and NDK r28 (`ndkVersion` in `composeApp/build.gradle.kts`).
  Point Gradle at the SDK with `ANDROID_HOME` or `local.properties` (`sdk.dir=…`).
- **iOS:** a Mac with Xcode 15+ and [XcodeGen](https://github.com/yonaskolb/XcodeGen).

## Android

```sh
cd apps/mobile
./gradlew :composeApp:assembleDebug        # APK in composeApp/build/outputs/apk/debug/
./gradlew :composeApp:installDebug         # install on a running emulator/device
```

From the repo root with Turborepo: `bun --bun x turbo run build --filter=@mothr/mobile`
(the `--bun` flag runs turbo's launcher on Bun instead of Node).

The debug build includes `arm64-v8a` (phones) and `x86_64` (emulators).

## iOS

```sh
cd apps/mobile/iosApp
xcodegen generate
open Mothr.xcodeproj
```

The Xcode build runs Gradle (`embedAndSignAppleFrameworkForXcode`), which builds the Rust client
for the simulator or device and links it into the `ComposeApp` framework. Targets:
`iosArm64` and `iosSimulatorArm64`, with iOS 16 as the minimum.

## Pairing

1. On the desktop: Settings → Remote → turn Remote on.
   With Tailscale, keep it on on the phone too, signed in to the same account. Nothing else is
   needed: Mothr listens directly on the computer's Tailscale address.
2. On Android, tap **Scan QR code** and scan the code on the desktop. It uses Google's code
   scanner, so it needs Google Play services but no camera permission.
3. Or copy the pairing link (`http(s)://…/?token=…`) and paste it into the app. This is the only
   way on iOS for now.

The link carries a secret token, so treat it like a password.

## Several computers

A phone can pair with any number of computers, such as a home and a work PC. Tap the computer's
name under "Chats" to switch, rename, unpair or add one. Every paired computer stays connected,
so any of them can notify you, and a notification's answer goes to the computer that asked.
Pairing again with the same computer updates its entry instead of adding a second one.

To try the app without a desktop session, run the fake hub:

```sh
MOTHR_DEMO_TOKEN=devtoken-devtoken-devtoken MOTHR_DEMO_PORT=7979 cargo run -p mothr-remote --example demo
```

Then pair the Android emulator with `http://10.0.2.2:7979/?token=devtoken-devtoken-devtoken`.
